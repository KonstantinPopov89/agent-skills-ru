# Передача работы в новый чат

После законченного этапа или по явному запросу сохрани состояние в каталоге работы. Когда активное окно ещё удобно и пользователь просит только сохранить точку возврата, продолжай в этом чате. Передавай только материалы, которые разрешено читать следующему участнику.

**TASK.md хранит слова заказчика.** Возьми точное первое сообщение о цели из доступного диалога. Если текст недоступен, запроси его или укажи пробел. Передай его файлом или на стандартный ввод в [handoff_anchor.py](scripts/handoff_anchor.py). Нужен Python 3 на macOS или Linux. Скрипт использует системную блокировку при одновременной записи. В командах ниже рабочая директория содержит папку `skills` этой коллекции, `work` обозначает каталог передаваемой задачи.

```bash
python3 skills/handoff/scripts/handoff_anchor.py init work --file request.txt
python3 skills/handoff/scripts/handoff_anchor.py append work --kind goal --file scope-change.txt
python3 skills/handoff/scripts/handoff_anchor.py check work
python3 skills/handoff/scripts/handoff_anchor.py prompt work
```

Через `append --kind goal` добавляй последующие сообщения, которые меняют цель, приёмку или объём. Если сообщение задаёт только порядок работы, используй `--kind procedure`. Первое сообщение о предмете задачи обязательно, даже если последнее сообщение звучит как "начинай". Рядом с TASK.md скрипт хранит контрольные суммы в `.TASK.seal.json`. Переноси весь каталог после завершения записи, включая скрытые файлы. Незавершённая транзакция восстанавливается при следующем обращении. При несовпадении сверь файлы с сохранённым экземпляром, прежде чем восстанавливать историю. Контрольная сумма помогает заметить случайную правку.

**STATE.md хранит состояние.** Возьми [шаблон](references/STATE-template.md). Укажи готовые результаты и их расположение, основания решений, открытые вопросы, неудачные попытки с причиной и ближайшее действие. Сохраняй краткую запись по завершённому этапу. Слова заказчика о задаче остаются в TASK.md. Важное ограничение среды запиши рядом с тем шагом, который от него зависит.

**При переходе** передай вывод `prompt` и доступ к каталогу. Команда только печатает текст. Создавай новый чат, если пользователь это поручил и клиент поддерживает такое действие. Иначе дай текст для вставки. На другом компьютере перенеси папку и запусти `prompt` ещё раз, чтобы в тексте появились новые пути.

**При возобновлении** прочитай TASK.md, проверь `check`, затем открой STATE.md. Перед исполнением сверь текущую ветку, версию данных и доступность файлов, от которых зависит следующий шаг. Если передачи уже было несколько, исходное поручение и поправки к нему по-прежнему лежат в TASK.md. Перед сдачей отметь по каждому требованию, где результат, что осталось и какие изменения согласовал пользователь.
