# Разведка идей

Используй для просьбы «дай идеи по этим источникам» или для записи решения по уже показанным идеям. Входом могут служить переданные заметки, отчеты, документы и код проекта. Заранее определенные каталоги, подписки и аккаунты не требуются. Если период не задан, ориентируйся на последние 30 дней и покажи фактически доступное окно. Для регулярного обхода период и разрешенные источники задает пользователь.

## Найти и отобрать

1. Прочитай предыдущие идеи и решения в журнале, если он ведется. Запиши фактический охват каждого выбранного источника: период, доступные документы, пропуски. Недоступный источник ограничивает вывод. Даже при хорошем охвате наблюдения, которых нет в документах, останутся неизвестными.
2. Сделай два прохода. В первом найди повторяющуюся проблему, запрос, аномалию или обещание без следующего действия. Во втором перечисли уже доступные процессы, данные и инструменты, затем сопоставь их с потребностями других участков. Например, место, где заявки регистрируют повторно, может воспользоваться уже отработанным импортом. Проверь, что доступ, формат и права применимы в новом контексте.
3. Открой хотя бы один внутренний источник для каждой идеи и укажи точное место. Внешний пример может подсказать метод, но не доказывает потребность конкретного получателя. Работай с материалами в согласованных границах. При переносе метода между клиентами или командами сохраняй раздельность их закрытых записей. Пропусти личные сведения, не относящиеся к задаче.
4. Сверь с журналом и действующим планом. Если действие уже запланировано, поясни существенную добавку или исключи его из новых идей. «Нет» учитывай до появления нового основания, которое сможешь назвать. «Потом» верни на рассмотрение после четырех последующих обычных разведок, ретроспективу в этот счет не включай. Для известных идей сохраняй прежние идентификаторы.
5. Верни до 3–5 обоснованных идей при достаточных данных. Для каждой укажи, что сделать, кому это нужно, что действительно ново, где основание, каких эффектов можно ожидать, что придется затратить и чем проверить за один небольшой шаг. Количественный эффект требует расчета с размерностями, ожидаемый эффект без расчета обозначь как гипотезу. Если удалось подтвердить меньше кандидатов, укажи наблюдаемый предел.

Запись «беру» означает решение владельца рассмотреть или делать идею. Она сама по себе не дает полномочий на реализацию или отправку. У выпуска, подготовленного для отдельного читателя, можно независимо проверить соответствие первоисточникам через [fresh-eyes](../fresh-eyes/SKILL.md). Если четыре обычные разведки подряд прошли без принятой идеи, сообщи об этом и предложи пересмотреть источники или частоту. Действующий внешний график изменяй только по соглашению с его владельцем.

## Локальный журнал

Включенный [скрипт](scripts/journal.py) работает с Python 3.9+ и стандартной библиотекой. Он хранит идеи, выпуски и историю решений в одном локальном файле SQLite. Укажи собственный путь в существующем приватном каталоге вне публикуемого репозитория. Каждый выпуск регистрируется одной транзакцией; ключ выпуска, например `demo-week`, защищает от случайного повторного добавления. При повторе с тем же ключом и теми же данными возвращаются прежние номера. У одного дня может быть несколько разных выпусков.

Команды ниже выполняются из каталога скилла. Для пробы выбери свободное имя базы в своем рабочем каталоге.

```sh
mkdir -p "$HOME/skill-demo"
python3 scripts/journal.py --db "$HOME/skill-demo/ideas.sqlite" record --input examples/issue.json
python3 scripts/journal.py --db "$HOME/skill-demo/ideas.sqlite" mark ID-20300107-1 later
python3 scripts/journal.py --db "$HOME/skill-demo/ideas.sqlite" status
python3 scripts/journal.py --db "$HOME/skill-demo/ideas.sqlite" check
```

У входного JSON ключ выпуска `key`, дата `date`, `trigger` (phrase, schedule, probe или retro), текстовое поле `period`, объект `sources` со статусом и охватом и массив `ideas`. У каждой новой идеи есть короткое `title`, номер прохода `move` (1 или 2) и непустой список `locators`. Для знакомства используй [учебный выпуск](examples/issue.json) и [две вымышленные заметки](examples/notes.md). Пустой массив идей допустим для проверенного окна без подходящих находок.

После `record` поставь полученные идентификаторы рядом с идеями в выдаче. Предложи читателю отметить «беру N / нет N / потом N», сопоставляя N с конкретным выпуском. Команда `mark` принимает только `take`, `no`, `later` и известный идентификатор. `status` выводит охват выпусков, идеи с локаторами, последнюю отметку и признак возврата отложенных; `check` проверяет целостность базы и связи. При работе без журнала ограничься разовой выдачей и сообщи, что историю решений не сверял.
