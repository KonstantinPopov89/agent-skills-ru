# Проверка пригодности результата

Возьми исходную задачу, адресата, принятые ограничения и проверяемую версию результата. Представь действие, которое человек должен суметь выполнить на этом этапе. У учебной инструкции это может быть самостоятельный выбор формулы, у отчета решение, для которого сравниваются показатели.

1. Восстанови цель и условия применения. Проверь, действительно ли предложенный показатель отражает эту цель. Для промежуточного этапа достаточно проверить его согласованную функцию.
2. Пройди центральное действие на содержательном примере. Используй исходные знания и инструменты, доступные адресату. Проследи путь от входа до решения, включая хотя бы один изменяющий действие выбор, когда он существенен. Отметь, где тебе пришлось незаметно добавить отсутствующий метод или данные. Задание «самостоятельно рассчитайте» годится, если владение способом было оговорено. Для обещанного обучения самому способу требуется объяснение выбора и расчета.
3. Проверь значения решающих полей, их период, единицы и охват. Поищи другое устройство реального процесса, которое дало бы тот же результат и изменило решение. При открытой задаче используй [ракурсы](../knowledge-perspectives/SKILL.md). Один контрпример может опровергнуть «все», но еще не опровергает наблюдение о среднем.
4. Если цена ошибки высока, до теста сформулируй, какое наблюдение заставит сузить вывод. Открой первичное основание или исполни центральный сценарий. Для отрицательного результата убедись, что событие можно было обнаружить и ожидаемый срок прошел. Если две версии дают одинаковый прогноз, назови ограничение проверки. У разрешимого пропуска добудь недостающие сведения. Непроверенное остается неизвестным.
5. В разрешенных правках исправь подтвержденный дефект во всех зависимых расчетах, выводах и примерах, затем повтори затронутый сценарий. Для аудита без редактирования укажи место, последствия и способ проверки. Законченный результат с зеленой технической проверкой может по-прежнему не решать согласованной задачи.

Для аналитики и управленческого решения открой [вопросы к данным](references/analysis-and-decisions.md). Для кассовых данных дополнительно используй [предметный адаптер](references/park-cashier-data.md) со скриптом, спецификацией и учебным набором. Для нескольких независимых замечаний пригодятся [правила приоритета](references/findings-and-priorities.md). В простой ситуации хватит основного прохода.

При внутренней проверке выдай сам результат и только существенные оговорки. При явном аудите назови, что проверено на практике, что изменило решение и что остается неизвестным. Если потребовалось исправление, сообщи, что именно изменилось. Технический тест, прогон моделью и наблюдение за реальным пользователем подтверждают разные вещи.
